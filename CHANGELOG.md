# Changelog
All notable changes to `@fluffy-spoon/substitute` are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Upgrading? Read the [migration guide](MIGRATION.md).

## [2.0.1] - Unreleased
The first stable release of version 2 (there was no 2.0.0 release). It is published as the npm `latest` version, which was 1.208.0 until now. See the [migration guide](MIGRATION.md) for upgrading from 1.x or from a beta.

### Added
- Symbols for the library's methods, exported from the package root: `received`, `didNotReceive`, `clearReceivedCalls`, `mimick`, `configure`, `returns`, `throws`, `resolves`, `rejects` and `mimicks`. They always mean the library's method, so they handle members with the same names, and they work when two copies of the package are installed.
- `sub[configure]()`: a view of a substitute in which every call and property read is a setup. Use it to change a call that is already configured, or to configure a mimicked substitute. A setup through a member or call that answers with a substitute goes to that substitute; through one that answers with a real value, it throws a `SubstituteException`.
- `sub[mimick](instance)`: hands everything that is not configured to a real instance. Calls are still recorded, and setups still win. A method or getter of the instance that returns the instance itself (a fluent `return this`, as in builders, `EventEmitter.on()` or `stream.setEncoding()`) answers with the substitute, so a chain stays on the substitute and each of its calls is recorded. A method read from the substitute is a handle that calls the instance's function as it was when it was read, as on an ordinary object, so wrapping a member and forwarding to it (`const original = client.query; client.query = function (...args) { return original.apply(this, args) }`, as instrumentation libraries, retry decorators and spies do) runs the original once and records the call once, and the spies of jest, vitest, node:test and sinon (`sinon.replace()`; `sinon.spy()` and `sinon.stub()` throw) put their wrapper on the instance, behind the substitute, so setups still answer first (see the README, "Partial mocks" and "Test runners"). In TypeScript, it takes a partial instance of an object type (`client[mimick]({ baseUrl: '' })`), and in generic code a `T`, also for a substitute of `T | undefined` or `T | null`.
- `sub[clearReceivedCalls]()`: forgets the received calls of a substitute and its auto-substitutes, and keeps the setups.
- `SubstituteException` is exported from the package root, for `instanceof` checks.
- Auto-substitutes are cached, so nested setups and checks work at runtime: `app.getCalculator().add(1, 2).returns(99)` and `app.logger.received().info('hi')`.
- `Arg.all()` after other arguments matches the rest of the arguments, including none: `log('x', Arg.all())`. In TypeScript, this type-checks after up to 6 other arguments.
- Matchers inside plain objects and arrays, also nested ones: `repository.save({ id: Arg.any(), name: 'bob' }).returns('saved')`. `Arg.all()` as the last item of an array matches the remaining items. The search for them is bounded (arrays and objects with up to 1,024 items or keys, up to 32 levels deep, and up to 32,768 items and keys per argument), so large arguments stay fast, and an array or object with more than 256 items or keys that holds no matcher is searched at most on the first two calls that pass it (only on the first if the limits left nothing inside it out).
- A native ES module entry point and an `exports` map, with typings for the `node16`, `nodenext` and `bundler` module resolutions. The ES module entry point shares one copy of the library with CommonJS. It is checked on every change with Node.js, Rollup with `@rollup/plugin-commonjs`, webpack, esbuild, a Vite SSR build with `ssr.noExternal` and vitest with `server.deps.inline` (also with `deps.interopDefault: false`). Bundles with CommonJS output that keep the package external load the CommonJS entry, so their default import is the exports object, and ts-node's ESM loader type-checks the default import against the CommonJS typings; use the named import `import { Substitute, Arg } from '@fluffy-spoon/substitute'` there (see the README, "Importing").
- `console.log`, `util.inspect`, `String()` and `JSON.stringify()` show a substitute's setups and received calls, also those of its auto-substitutes (at most 50 calls and 50 setups of them), under their paths. An auto-substitute shows its path, such as `@Substitute.logger` or `@Substitute.getUser(1)`, and its own setups and calls. Printing always ends, also for substitutes stored in the arguments of their own calls, and for chains of any length (long paths are shortened in the middle). Each value is printed within bounds, so that a large argument, such as a DOM event that refers to its window or an object with thousands of keys, takes a few lines: two levels deep, as `util.inspect()` shows values by default (`{ a: { b: { c: { d: 1 } } } }` prints as `{ a: { b: { c: [Object] } } }`), with the first 20 items of arrays, `Map`s and `Set`s and the first 20 keys of objects, and at most 1,000 characters (values that fit print as `util.inspect(value)` prints them). Matchers inside objects and arrays are shown by their own label at any depth. Errors, in printouts and failure messages, show as `[Name: message]` without their stack, also inside objects and arrays, followed by their own properties and their `cause`: `[HttpError: not found] { status: 404 }`. An array of more than 1,000 items whose first items print in such a short form is printed without its other keys (such as `total`), so that printing an array of a million errors takes well under a millisecond.
- `new` on a substitute or on a member of it (`new sdk.Client('https://api')`, also through `Reflect.construct()`) is a call: it is recorded, setups written as calls answer it (`sdk.Client(Arg.any()).returns(client)`), and checks written as calls count it (`sdk.received(1).Client('https://api')`). In TypeScript, these setups and checks compile for constructor types (for each of their construct signatures) and for members that are classes. A class can extend a substitute or a member of it (`class Plugin extends sdk.Base`): `new` gives an instance of the subclass, constructed by a mimicked class with the subclass as `new.target`, and the class has the `call`, `apply` and `bind` of every function, so `new (Plugin.bind(null, 'audit'))()` constructs it. Such instances are ordinary objects: passed to a substitute, they are recorded and compared like other objects, and `JSON.stringify()`, `util.inspect()` and the printing of jest and vitest show their own fields. What Node.js reads through them while the library compares or prints them (`href`, `protocol`, `auth`) is not recorded on the substitute, also when another copy of the package does the comparing or printing: the copies share a marker for that on the global object, under `Symbol.for('@fluffy-spoon/substitute:guard')`.
- `Arg.any('bigint')`.
- The asymmetric matchers of jest and vitest (`expect.any(String)`, `expect.objectContaining(...)`, `expect.stringContaining(...)`, ...) and sinon's matchers (`sinon.match.has('err')`, ...) work as argument matchers in setups and checks, also inside objects and arrays, and failure messages show them as the runner does (`Any<String>`), also nested in the sample of another one at any depth (`ObjectContaining { input: ObjectContaining { items: ArrayContaining [ 3 ] } }`). A value that cannot be read, such as a revoked proxy, is never taken for one. In 2.0.0-beta.4 they were compared as values, so a `didNotReceive()` check with one passed whatever was called, and a setup with one never answered. `Arg` matchers work inside them (`expect.objectContaining({ topic: Arg.any('string') })`), and in the equality of jest and vitest themselves (`expect(order).toEqual({ id: Arg.any() })`, `toHaveBeenCalledWith(Arg.any('string'))`), through an `asymmetricMatch()` method of their own (there, `Arg.all()` stands for one value, and snapshots do not keep them as property matchers); sinon's matchers compare an `Arg` matcher inside them as a value, so use sinon's own matchers there.
- TypeScript: `.resolves()` and `.rejects()` on every member that a native promise of the value fits, such as `void | Promise<void>`, `string | Promise<string>` or `PromiseLike<T>` (2.0.0-beta.4 offered them only when the return type is a promise). A thenable with members of its own, such as a query builder, is configured with `.returns()`.
- TypeScript: `.returns()` and `.resolves()` without a value whenever `undefined` is a valid value (`any`, `unknown`, `void`, `undefined` and `T | undefined`, as in Koa's `next().resolves()`); 2.0.0-beta.4 allowed it only for `void`.
- A check that nothing follows, such as `next.didNotReceive()` or `sub[received](2)` as a statement, checks nothing, and is reported as a `SubstituteException` from a microtask, with the forms that complete it. A string-form call that is most likely a member of the substituted type (configured, answered by a mimicked instance, or with arguments that a check cannot have) is not reported. Each such check is reported, also when the same check is made again and completed later in the same synchronous code. Of the checks written with the symbols, the first 1,000 of a synchronous run record where they were made (most of what such a check costs); a later one is reported without the line of the test, and a matcher that throws for invalid use in its own arguments does not cancel its report.
- **JavaScript:** a matcher function passed without calling it as an argument of a setup or a check (`Arg.any` instead of `Arg.any()`, also `Arg.any.not`, `Arg.is`, `Arg.is.not` and `Arg.all`) throws a `SubstituteException` that suggests the call. Such a setup never answered, and such a `didNotReceive()` check always passed. An `Arg.is()` predicate that returns a promise or another thenable throws a `TypeError`, also inside an object or an array, and leaves no unhandled rejection.
- A substitute that configures or mimicks `toString()` or `valueOf()` converts to their result in template strings, `String()`, `+`, `==` and comparisons, following JavaScript's rules; a mimicked instance's own `Symbol.toPrimitive` is used as it is. Such conversions are recorded as calls. `util.inspect()` and failure messages still show the printout.
- A substitute that mimicks an object enumerates like it: `Object.keys()`, `Object.entries()`, spread, `Object.assign()` and `for...in` see the instance's enumerable own keys (and read the values through the substitute), and `JSON.stringify(sub)` gives what `JSON.stringify(instance)` gives. The property descriptor of a mimicked method has the method's handle on the substitute as its value, and `Object.defineProperty()` and `delete` on such a substitute change the instance.
- When a check fails because the code under test passed another substitute, so that the expected call and a received one print alike, the message numbers the substitutes in it (`@Substitute#1`, `@Substitute#2`, ...) and says so. The substitutes of another copy of the package are numbered as well. When they print alike because they differ deeper than two levels, as filters of an ORM often do, the message prints both deeper, up to four levels, also for differences inside `Map`s and `Set`s and among the other keys of an array; a matcher in the expected call, such as `Arg.any('string')` for a generated id, does not count as a difference there, and neither does an order that matching ignores: of keys (`{ ...input, id }`), of the entries of `Map`s and `Set`s, of the properties of errors and functions, and such orders inside them. The substitutes are numbered by the same rule, so also when the calls differ only where the expected call has a matcher, or only in such an order. When an expected call still prints exactly like a received one that it does not match, as for objects that hold functions (the commands of the AWS SDK) or `#private` fields, or symbols of the same description, the message ends with a note that says why they can differ, and to use `Arg.is()` or the same instance.
- The public typings carry documentation comments for editors: `Substitute.for`, `SubstituteOf`, `Arg` and its matchers, the setup methods, the checks and the symbols. At `Arg.is.not(...)` and `Arg.any.not(...)`, editors show the documentation of the inverse matcher.
- A [migration guide](MIGRATION.md), this changelog and [contributing guidelines](CONTRIBUTING.md). The README examples are type-checked and run in CI, and the oldest supported TypeScript version is checked there, too.

### Changed
- When several setups match a call, the most specific one wins: literal arguments, then matchers, then `Arg.all()` alone. Among setups of the same kind, the most recent one wins, and configuring the same call again replaces it. (The README said that the first matching setup wins.)
- A call with an argument matcher (`Arg.any`, `Arg.is`, `Arg.all`, also with `.not`, also inside an object or array) is always a setup or a check. It is never recorded as a received call and never runs an existing setup.
- The reads and calls that lead up to a setup or a check in the same expression, like `app.getCalculator()` in `app.getCalculator().add(1, 2).returns(99)`, are not recorded as received calls. Calls that the code under test made are kept, also when the test then configures or checks the value they returned. That includes calls through a method that the test handed to the code under test (`new UserService(api.getUser)`), which are made, and shown in failure messages, where the code under test invokes them, also with the substitute as `this` (`Reflect.apply(fetch, api, [id])`), and calls from a promise job (`Promise.resolve(id).then(getUser)`). A member configured to return another substitute counts like an auto-substitute here: after `app.getCalculator().returns(calculator)`, `app.getCalculator().add(1, 2).returns(3)` records no `getCalculator()` call. A check that a helper opens and returns for its caller to complete (`const sentTo = (io, room) => io.to(room).received(1)`) belongs to the expression that opens it, wherever it is completed.
- Reading a method without calling it is no longer a call; method checks count invocations only.
- `.call()`, `.apply()` and `.bind()` on a substitute value also count as a call of a member called `call`, `apply` or `bind`, and a setup written through them configures that member. Failure messages and `String(sub)` show such a call once, as in `rpc(1) via .call('getUser', 1)`. A nested setup or a check through an unconfigured `call` or `apply` whose first argument is `undefined`, `null`, an object or a function, as in a wrapper's `fn.apply(this, args)`, goes to the auto-substitute of the direct call. With a primitive first argument, as in an RPC client's own `client.rpc.call('getUser', 1)` or ioredis' `redis.call('get', key)`, the invocation has an auto-substitute of its own for its arguments as they are, so `client.rpc.call('getUser', 1)` and `client.rpc.call('deleteUser', 1)` stay apart. An API whose own `call` takes an object first, such as web3's `method.call({ from })`, shares the auto-substitute of `method()` for every object unless a call is configured (see the README, "`call`, `apply` and `bind`").
- A `mimicks()` function and a mimicked function get the `this` of the call: the substitute for `sub.method(...)`, and the first argument of `.call()` and `.apply()`.
- **JavaScript:** `sub.received(count)` or `sub.didNotReceive()` followed by `.returns()`, `.throws()`, `.resolves()`, `.rejects()` or `.mimicks()` configures a member of your own called `received` or `didNotReceive`. In 2.0.0-beta.4 and 1.x it was a check of a member called `returns` (and so on), so such checks now pass silently. Use the symbols: `sub[received](1).returns(5)`.
- **JavaScript:** `sub.received(count)` or `sub.didNotReceive()` followed directly by a call, like `listener.received(1)('saved')`, checks a call of the substitute itself.
- `received(count)` throws a `SubstituteException` unless the count is a non-negative integer (or left out). In 2.0.0-beta.4 an invalid count threw a plain `Error`, and in 1.x it was reported as a call count mismatch. `received(0)` is the same as `didNotReceive()`.
- `Arg.any('object')` matches objects, arrays and substitutes, but no longer `null`. `Arg.any('function')` matches substitutes, and `Arg.any('array')` uses `Array.isArray`.
- `Arg.is()` throws a `TypeError` right away when it is not given a function. A predicate that throws counts as a non-match, and the failure message says so.
- **JavaScript:** `Arg.any(type)` and `Arg.any.not(type)` throw a `TypeError` right away for a type name that they do not know, such as a typo. In 2.0.0-beta.4, `Arg.any('strnig')` matched nothing and `Arg.any.not('strnig')` matched every value. `mimicks()` with something other than a function throws a `TypeError` at the setup, naming the member, instead of failing later in the code under test.
- An argument that a call leaves out at the end counts as `undefined`, as in 1.x: it matches a literal `undefined` and matchers that accept `undefined` (`Arg.any()`, `Arg.any('undefined')`), and `f(1)` and `f(1, undefined)` are the same call. In 2.0.0-beta.4, an omitted argument matched nothing. So `didNotReceive().f(Arg.any())` now fails after `f()`, and a literal setup that a matcher setup already answers (`multiply(1).returns(1)` after `multiply(1, Arg.any()).returns(10)`) needs the `configure` view.
- An argument object that is changed after it was used in a setup only matches that setup when the same object is passed again; a new object equal to the changed one no longer does. (The library remembers the hash of an object with more than 256 keys, or of a `Map` or `Set` with more than 256 entries, between calls, but an object that changed after an earlier call still matches a setup made with an equal object.) Whether a new array or object around an argument object that changed after the setup matches the setup is not specified.
- `Symbol.iterator`, `Symbol.asyncIterator`, `Symbol.hasInstance`, `Symbol.isConcatSpreadable`, `Symbol.match`, `Symbol.matchAll`, `Symbol.replace`, `Symbol.search`, `Symbol.split`, `Symbol.species`, `Symbol.toStringTag`, `Symbol.unscopables`, `util.promisify.custom` (also the running Node.js' own symbol, which differs on Node.js 10.0 to 12.16.1 and 13.0 to 13.11), `asymmetricMatch`, `_isMockFunction`, `calledWithExactly` and `handleEvent` read as `undefined` unless they are configured, and these reads are not recorded. So a substitute is no longer iterable: `[...sub]` and `for...of` throw a `TypeError` (2.0.0-beta.4 iterated it as empty), jest snapshots show a substitute as `[Function]` instead of a mock function, sinon-chai's assertions throw `... is not a spy or a call to a spy!` for a substitute instead of passing (`expect(next).to.have.been.called` passed on a substitute that was never called; jest's spy assertions still take a substitute for a spy, see the README, "Test runners"), and happy-dom calls a function substitute added with `addEventListener()` itself, as Node.js and jsdom do, instead of its member `handleEvent`. `__esModule` is still an ordinary member, so a substitute that stands in for a whole module counts as an ES module, and its default import is the auto-substitute `sub.default`; the README ("Mocking a whole module") shows how to make it the substitute itself.
- A substitute no longer exposes internal fields: `Object.keys(sub)` is empty, unless the substitute mimicks an object (see above), and `Reflect.ownKeys(sub)` gives the non-enumerable `length` and `name` that every function has (`length` is `0`, `name` is the member's name for a member, such as `'getKey'`, and `''` otherwise), so `util.callbackify(sub.method)` and wrappers that copy a function's name work (2.0.0-beta.4 listed `length`, `name` and `prototype` of the library's internal function, with its internal name).
- `key in sub` is `true` for a key with a setup, a key of a mimicked instance and a property defined with `Object.defineProperty()`, and `false` otherwise (calls and checks through a call with a matcher do not count as setups); it records nothing, and its cost does not depend on the number of auto-substitutes. In 2.0.0-beta.4 it answered for the library's internal function (`true` for `call` and `length`, `false` for configured members).
- Failure messages say what kind of call was expected: method calls, property reads, property assignments, or "property reads or method calls" when that is not known. They show the path of nested substitutes, also for a substitute passed as an argument (`@Substitute`, `@Substitute.child`), of the same or of another copy of the package (2.0.0-beta.4 printed it in full, with its calls), show a call made with `new` as `new Client(...)`, and list at most 50 received calls, and no more once the listed calls take 20,000 characters. When the checked member was never used at all, the message cannot name the expected arguments; once the method has been called, it does. A method check of a member that was only read, never called, fails with a hint that reading is not calling, whatever the expected count (for `didNotReceive()`, also how to reset the reads); its message says "property reads or method calls" when the count differs from the number of reads. A member whose setups give values that cannot be called (`returns()` of a value that is neither a function nor a substitute, `resolves()`, `rejects()`, `throws()`, or a mimicked instance's value that is not a function) is checked as a property instead: "Expected to receive 1 property read matching port, but received 2.", without a hint, also by a check with a call whose count differs from the number of reads; a check with a call whose count equals the number of reads, or with no count (`config.received(2).port()`), fails as a method check, and its last line says that the reads answered a value that cannot be called, and gives the check without the call (`sub.received(2).port`). When a check fails because the member was called only further down an unconfigured chain, as the second call of `reply.code(404).send(body)` or `span.setAttribute(key, value).setStatus(status)` is, the message names up to three such places and says to make each method on the way return the substitute (`sub.code(Arg.all()).returns(sub) and sub.header(Arg.all()).returns(sub)` for `reply.code(404).header(name, value).send(body)`) or to mimick an instance whose methods return `this`, or, when a property is read on the way, which substitute to check, by its whole path (`sub.users.where({ id: 1 }).limit(1).received(1).exec(...)`), written as code that can be run (`sub['my-key']`, `sub[Symbol.for('k')]`, the concrete call that a shared substitute was returned to), or not given when it cannot be written. The calls of a substitute that a setup with matchers gives every call that it matches are shown with the call that it was returned to (`@Substitute.to('room-a').emit(...)`), and when it was returned to calls with different arguments, a line under the list of calls names them. Messages contain ANSI colours only when the output is a terminal, and honour `NO_COLOR`, `FORCE_COLOR`, `NODE_DISABLE_COLORS` and `TERM=dumb`.
- Failed checks throw right away. Only a check that nothing follows (see above), and a property-style check (`sub.received(2).member` or `sub.didNotReceive().member`, not followed by a call) on a member that was called as a method, are reported later, from a microtask (see the README). Such a report uses the `queueMicrotask` that the library found when it was loaded (`process.nextTick` on Node.js 10). 2.0.0-beta.4 used `process.nextTick`, from which jest cannot attribute an exception to a test; jest now reports the failure of the running test (jest 30 on Node.js 22: of the test file). mocha ties such a failure to the test only in an `async` test, which it then reports a second time ("done() called multiple times") before it goes on, or, when the test's promise settles after the last test, throws that second error after the summary and exits with code 7; after a synchronous test, it stops the run. ava cannot tie it to a test, and ends the worker of that test file (see the README, "Assertions that fail later"). A matcher that throws its `TypeError` for invalid use cancels such a report only when it belongs to the same check (called on the same line as the member is read, in the same function).
- With "pause on caught exceptions" on, a debugger stops inside the library (twice for each step of a chain such as `app.repo.users.find(1)`) where `Error.prepareStackTrace` is not a function: on Node.js before 20.20 without an installed formatter, and in `vm` contexts such as jest 30's test environment and vitest's `vm` pools (2.0.0-beta.4 did not stop there). Add `**/node_modules/@fluffy-spoon/substitute/**` to the debugger's `skipFiles` (see the README, "Debuggers").
- TypeScript: on a type with a member called `received`, `didNotReceive`, `returns`, `throws`, `resolves`, `rejects` or `mimicks`, only the symbol forms `sub[received]()` and `sub[didNotReceive]()` are offered. In generic code, the type parameter's constraint decides; an unconstrained `SubstituteOf<T>` offers the string forms. `.returns()` and the other setup methods are offered unless the configured value has its own member with that name.
- TypeScript: `.resolves()` and `.rejects()` are no longer offered for subtypes of `Promise` with members of their own, such as ky's `ResponsePromise`, knex's `QueryBuilder`, execa's result or a `CancellablePromise` with `cancel()`. 2.0.0-beta.4 offered them, and the code under test then failed with "... is not a function" when it called one of those members on the native promise. Configure such members with `.returns()` (see the README, "Working with promises"). Subtypes without members of their own, such as Prisma's `PrismaPromise`, keep them.
- TypeScript: a member called `then` is typed `never`, because substitutes are never thenables.
- TypeScript: with `declaration: true` (or `composite: true`), a file can export a substitute, a check view (`export const view = pet.received()`, also of a union substitute) and a function that returns one, but not the value of a member or a call of a substitute (`export const sum = calc.add(1, 2)`) or the `configure` view, which fail with TS4023 ("has or is using name 'returns' ... but cannot be named") because their setup methods are keyed by the library's symbols; 2.0.0-beta.4 emitted declarations for them. Give such a value the member's type (`export const sum: number = calc.add(1, 2)`), or export a function that sets up and returns the substitute (see the README, "Typing limitations"). Check views of types with members keyed by symbols (iterables, `Map`, `Set`, Node.js' `EventEmitter`, streams and servers) can be exported as well. Generic helpers whose inferred type is a substitute of `T | undefined` or `T | null`, or a member or check view of a substitute of a constrained type parameter, need a type annotation: without one, TypeScript 3.6 does not finish, 4.5 runs out of memory, and 4.1, 4.9, 5.0 and 5.2 report TS7056 ("The inferred type of this node exceeds the maximum length the compiler will serialize"), and so do 5.4 and newer for the members and check views of a constrained type parameter (see the README for the annotations that work). The declaration files that TypeScript 5.9 or older emits with `moduleResolution: node` for a member of a check view or an exported matcher refer to the directory `@fluffy-spoon/substitute/dist/shared`; the `exports` map sends it, and `dist/api` and `dist/api/types`, to their index, so `node16`, `nodenext` and `bundler` projects read them with full types.
- TypeScript: members typed only `null` or `undefined` keep their plain type and have no setup API (configure them through `sub[configure]()`).
- TypeScript: `Arg.any('function')` is typed as any function or class, so it fits typed callback parameters. `Arg.any('object')` is typed `any`.
- TypeScript: `Arg.any('undefined')` only fits parameters and properties that accept `undefined`. It was typed `never`, which fit every parameter (`calculator.add(Arg.any('undefined'), 2)` compiled). `Arg.any.not('undefined')` fits any parameter.
- The minimum TypeScript version is 3.6 (2.0.0-beta.4 needed 3.8). The package runs on Node.js 10 and newer with CommonJS. As an ES module, it needs Node.js 12.17 or newer on 12.x, 13.7 or newer on 13.x, or 14 or newer.
- Because of the new ES module entry point, CommonJS code that `require()`s the package and is bundled with Rollup's `@rollup/plugin-commonjs` while the package stays external (also in the SSR builds of Vite 7 and older) gets the `Substitute` class from `require()`, unless the plugin's `esmExternals` option covers the package or the package is bundled. See the README, "Importing".
- Releases are published to npm with provenance: stable versions as `latest`, prereleases as `beta`.

### Fixed
- Configuring a call whose arguments overlap an existing setup ran that setup instead. It failed with `TypeError: ... returns is not a function`, or silently configured the wrong thing. This broke the README's "Match order" and "Partial mocks" examples.
- Checking a configured property ran its setup: it threw the configured error, used up values of a `returns()` sequence, ran `mimicks()` again or left an unhandled rejection.
- Calls through a stored or destructured method reference, or a callback, were recorded only once.
- Merely reading a method (for example to register it as a callback) satisfied `received().method(...)`.
- `.call()`, `.apply()` and `.bind()` on a configured method, on a function substitute, on the result of a call or on a nested member returned a proxy instead of the configured value, so a function substitute called through a helper like `once(fn)`, which calls `fn.apply(this, args)`, did not return its configured value. Without a configured value, they now give the same auto-substitute as the direct call, so the nested setups made on `api.getUser(1)` answer through `withRetry(api.getUser)(1)`, `jest.fn(fn)`, `vi.fn(fn)` and `sinon.spy(fn)` as well, and the calls made on what they returned are checked there.
- A setup on the substitute leaked into nested members with the same name, and nested checks (`app.logger.received().info('hi')`) passed whatever had been called, also through a call with a matcher (`app.repo(Arg.any()).didNotReceive().save(1)`). Such a check now counts the calls of the substitutes that the received calls matching it returned, step by step also further down (`app.repo(Arg.any()).db[received](2).query(Arg.any())`), including substitutes of another copy of the package, and changes nothing that later calls return; a check view that is used again counts like a new one. When a matching received call was answered with a value that is not a substitute, such as a promise of `resolves()`, a plain object of `returns()` or a function that `.bind()` made from a substitute, however the code under test made the call, and also when a read of a member on the way was, the calls on that value cannot be counted, so such a check throws a `SubstituteException` that says so, instead of passing. After a nested setup through a call with matchers (`io.to(Arg.any()).emit(Arg.all()).returns(true)`), every matching call answers the same substitute, as in NSubstitute; a check through a concrete call (`io.to('room-b').received(1).emit(...)`, also one written with `call` or `apply`, and one through a call answered by the substitute itself when it is on the same line) counts only the calls that came through that call, and is a `SubstituteException` when they cannot be told apart from those of other calls that the substitute was returned to. Such checks cost no memory per call, and each takes as long as the first.
- `sub.didNotReceive().method` without the call parentheses passed silently when the method had been called. It is now reported (see above).
- `Arg.all()` after other arguments ignored those arguments.
- Every call scanned all earlier calls, which made large tests slow. 10,000 calls now take well under a second, also with arguments such as nested objects, objects with cycles, errors, long arrays, `Buffer`s, long strings, URLs, or wide objects and `Map`s that many values share or that are passed with every call: 10,000 calls that each pass one table with 10,000 keys take about 0.1 seconds on Node.js 22, and 10,000 calls with different URLs (of the global `URL` class) about 0.09 seconds (the development builds after 2.0.0-beta.4 compared each URL with every earlier one: about 13 seconds).
- A failed check overflowed the stack when substitutes referred to each other through their arguments, and threw a `TypeError` with `Error.stackTraceLimit = 0`. The library also works with a read-only, getter-only, frozen (`Object.freeze(Error)`) or deleted `Error.stackTraceLimit`, and leaves the property as it is (in the development builds after 2.0.0-beta.4, the first three made every operation throw a `TypeError`). Where V8 collects no stack frames (a limit that is 0, missing, not a number or an accessor), the library captures none either; with a frozen `Error` it cannot read them. Then position alone decides which calls lead to a setup or a check (see the README).
- An exception thrown by an `Arg.is()` predicate escaped into the code under test.
- An `Arg.is()` predicate, or a matcher of a test runner, that reads or calls members of a substitute argument recorded these reads and calls on it and used up the values of its `returns()` sequences, in checks and when the calls of the code under test were compared with setups. Now what a matcher does to a substitute argument while it looks at it leaves no trace, and in a check, nothing that it does while it runs leaves one (an `async` callback that it calls is recorded after its first `await`). When a call of the code under test is compared with the setups, what the code under test does in a callback that a predicate calls, and what a predicate does to substitutes that are not among the call's arguments, are recorded as before; use `mimicks()` to call such callbacks (see the README, "Matching specific arguments").
- A revoked proxy among the arguments, such as an immer draft after `produce()` has finished, made every call, setup and check with it throw `TypeError: Cannot perform 'getPrototypeOf' on a proxy that has been revoked`. It now matches by identity, also next to a matcher, and prints as `<Revoked Proxy>` where Node.js' `util.inspect()` can print one (not on Node.js 16.9 and older). So does a proxy whose keys cannot be listed (its `ownKeys` or `getOwnPropertyDescriptor` trap throws). A revoked proxy of a function is a value like any other as well, also as the value of a setup, of a member or of a mimicked instance.
- `Object.setPrototypeOf(sub, prototype)` broke a substitute: later checks, assignments and `String(sub)` threw a `TypeError`. Now everything but `util.inspect()`'s printout keeps working, and `instanceof` sees the new prototype.
- `Object.freeze()`, `Object.seal()` and `Object.preventExtensions()` broke a substitute: later reads and setups threw a `TypeError`. `Object.defineProperty()` on a substitute threw a `TypeError`; it now defines a real property, which reads return without recording them. On a frozen, sealed or non-extensible substitute, `Object.setPrototypeOf()` with another prototype throws a `TypeError` that names the substitute (`@Substitute is not extensible: ...`; 2.0.0-beta.4: `function anonymous(...) is not extensible`), and so does `Reflect.setPrototypeOf()`, which returned `false`.
- Failure messages said "property calls" when the library could not know whether a method or a property was checked.
- A check reported later was lost when a test had installed fake timers that fake `process.nextTick`. Fake timers installed after the library is loaded no longer delay or swallow such a report.
- `[].concat(sub)` dropped the substitute, `value instanceof sub.SomeClass` was always `true`, `'text'.startsWith(sub.prefix)` threw, and `util.promisify(sub.method)` did not call the substitute.
- jest took every substitute for an asymmetric matcher: `expect(fn).toHaveBeenCalledWith(sub)` and `toContainEqual(sub)` passed whatever the values were, and a failing `toEqual(sub)` threw jest's internal "Unexpected return from a matcher function" error.
- TypeScript: optional members; named members next to an index signature; overloads without parameters; methods with more than 5 overloads; `.throws()` on methods returning `never`; `(...args: unknown[])` methods; a private member called `received` turning the substitute type into `never`; types with a very large union of string literals, such as lib.dom's `HTMLInputElement`, failing with "Expression produces a union type that is too complex to represent".
- TypeScript: a substitute of a function type or of an interface with call signatures had no setup or check API for its own calls. `listener('saved').returns('ack')`, `listener.received(1)('saved')`, `listener[received](1)('saved')` and `listener[configure]()('saved').returns('ack')` now compile.
- TypeScript: in generic code over a constrained type parameter (`<T extends Calculator>(sub: SubstituteOf<T>)`, or `Substitute.for<T>()` in a fixture class), call setups (`sub.add(1, 2).returns(3)`) and property checks (`sub.received().total = 1`) did not compile. Setups, checks and the new `configure` view now work through the constraint, also for keys that exist only through the constraint's string index signature (with exceptions, most of them on TypeScript older than 4.8; see the README, "Typing limitations").
- TypeScript: on a member whose type is a union of function types with different return types (`onResult: ((r: string) => number) | ((r: string) => string)`), and on methods of a union whose return types differ and that return a promise or `this` (`Substitute.for<Cat | Dog>()`), `.returns()` or `.resolves()` took `never`, and calls of a substitute of a union of function types had no setup API. They now take the union of the variants' return types: `pet.load().resolves(1)` and `pet.load().resolves('x')` for `Promise<number> | Promise<string>`.
- TypeScript: on a method that the variants of a union declare with different parameter lists (an extra optional parameter, other parameter types, other overloads), such as `read(path): string` and `read(path, encoding?): Uint8Array` in `Substitute.for<ReaderA | ReaderB>()`, `.returns()` was missing or took `never` when the return types differ, and on TypeScript 5.4 and newer it was missing even when they are the same (`fetch(url)` and `fetch(url, options?)`, both returning `Promise<string>`). Such methods now have the setup API, which takes the return types of the variants that the call can reach, depending on the number of arguments it passes (see the README, "Typing limitations", for the exact rule). Each call is checked against one variant's parameter list as a whole, so arguments that no variant accepts together do not compile, and a callback without parameter types gets them from that list. A callback that annotates `this` with the type of a variant whose method takes it compiles, too, also followed by `Arg.all()`.
- TypeScript: setups of the generic methods of Node.js' `EventEmitter<Events>` did not compile (`orders.emit('paid', 'o1', 20).returns(true)`: "This expression is not callable"; `orders.on('paid', listener).returns(orders)`), nor did `Arg.all()` after the event in a check of a typed `emit()` (`emitter.received(1).emit('saved', Arg.all())`). Generic methods now have the setup API, the checks and the `configure` view, with their type parameters replaced by their constraints (see the README, "Typing limitations", for what that cannot check). With `@types/node` 18.19.63 to 24.x, `emit()`'s leading arguments are checked against its own signature; from `@types/node` 25 on, a substitute takes any event and arguments there.
- TypeScript: in a property check on a substitute of a union (`Substitute.for<Cat | Dog>()`), a matcher could not be assigned to a member that is a function (`pet.received().speak = Arg.any('function')`). Functions and constructors (`String`, `Date`, classes) are still rejected there, as TypeScript rejects them for the union itself.
- TypeScript: an `Arg.is()` predicate had to return a `boolean`, so `Arg.is(user => user.name)` and `Arg.is(user => user.name?.startsWith('a'))` did not compile, although any truthy value matches. It can now return any value that is not a promise; an `async` predicate still does not compile.
- TypeScript: a setup with `Arg.all()` alone on an overloaded method took the value of the first overload, so `pool.query(Arg.all()).resolves(result)` did not compile with `@types/pg` (whose first overload returns a stream). On an overloaded method whose overloads return different types, `Arg.all()` alone now takes any overload's value, and `.mimicks()` a function that fits each overload, as a function assigned to the method does: it may leave out trailing parameters (`(entity: any) => ...`, `async path => ...`, `(text: string) => ...` for `@types/pg`'s `query(text, values?)` and `query(text, callback)`), and an untyped parameter gets the parameter types of all the overloads at its position, on every supported TypeScript version. A parameter that does not take what some overload passes is rejected (`(key: string) => key` for `get(): string[]` and `get(key: string): string`; make it optional). On overloads whose return types depend on their type parameters, such as TypeORM's `Repository.save()`, a function that returns its argument needs a type (`async (entity: any) => entity`), and a setup with `Arg.any()` for such an argument has no setup API (use `Arg.all()`, a typed `Arg.is()` or a cast; see the README, "Typing limitations"). When all the overloads return the same type, as fastify's `addHook` overloads do, `.mimicks()` takes the parameters of the first overload (of the last 8, which count).
- TypeScript: a method or callable member whose last overload no argument fits once its type parameters are replaced by their constraints, such as hono 4's `Context.get` and `Context.set` (`<Key extends keyof ContextVariableMap>(key: Key)` last, with an empty `ContextVariableMap`), had no setup API: `c.get('user').returns(user)` failed with TS2339, and `c.get(Arg.all())` matched no overload (TS2769). Such a last overload is now left out of the setup API, the `configure` view and the `Arg.all()` setup, when it returns `never` once its type parameters are replaced; how other impossible overloads are typed is in the README ("Typing limitations").
- TypeScript: a generic method whose return type is conditional on a type parameter (`convert<T>(value: T): T extends string ? number : boolean`) took only the type of one branch in `.returns()`. It now takes any value there.
- TypeScript: a union whose variants declare a member as only `null` or `undefined`, like `{ data: string[]; error: null } | { data: null; error: Error }`, turned the substitute into `never`.
- TypeScript: on a union whose variants have a string index signature (`{ kind: 'a'; [key: string]: unknown; speak(): 'meow' } | ...`), `.returns()` was missing or took `never`. It now takes the union of the variants' return types, as for other unions.
- Under native ES modules, the default import was the CommonJS module object, so `Substitute.for` was not a function.
- A function of the code under test that copies the prototype of a substitute or of a bound substitute method, as `mem`, `p-memoize`, `debounce-fn` and `onetime` do through `mimic-fn`, was taken for a substitute: `util.inspect()`, `console.log()` and failure messages printed it as one (2.0.0-beta.4: `@Substitute {undefined }`), and in the development builds after 2.0.0-beta.4, printing it threw, or called it and recorded calls that the code under test never made. It now prints as an ordinary function, with the name that the wrapper gives it (`mem(api.getUser)` copies the member's name, `[Function: getUser]`), and printing never calls it. The same goes for functions that the code under test binds with the function's own `bind`, a substitute (`Function.prototype.bind.call(listener, context)`) or such a wrapper (`mem(api.getUser.bind(api)).bind(null, 1)`, `util.promisify(fs.readFile).bind(null, path)`): 2.0.0-beta.4 printed them as substitutes (`@Substitute {undefined }`), and in the development builds after it, printing them threw `TypeError: current.records is not iterable` or `this(...) is not a function`, or recorded calls that the code under test never made.
- The package could not be loaded on Node.js versions before 14.18.
- A manual `npm publish` after `npm test` could publish a package without its entry point.

### Removed
- `Substitute.disableFor()`. Call members with conflicting names directly, and use the symbols for the library's methods.
- `sub.clearSubstitute(clearType)` and the `ClearType` export. Use `sub[clearReceivedCalls]()`, or create a new substitute to drop setups.
- The string `sub.mimick(instance)`. Use `sub[mimick](instance)`; `mimick` is now an ordinary member name.
- The deep import paths of 1.x (`dist/src/...`) and of the 2.0.0 betas (`dist/Substitute`, `dist/Arguments`, `dist/SubstituteException`, and internals such as `dist/SubstituteNode`, `dist/Recorder` and `dist/RecordsSet`). Import from the package root. Directory deep imports other than `.../dist/api`, `.../dist/api/types` and `.../dist/shared` (such as `.../dist/internals`) no longer resolve on Node.js versions that read `exports`.
- The GitHub Packages publishing job, which could not publish the `@fluffy-spoon` scope.
